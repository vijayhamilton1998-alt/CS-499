Databases

Artifact: Travlr Getaways

The artifact selected for the Databases category is the Travlr Getaways full-stack web application originally developed during CS 465 Full Stack Development. The application uses MongoDB as its database and Mongoose to define the data model and provide communication between the Node.js application and the database.

I selected this artifact because persistent data is a central part of the Travlr Getaways application. Travel packages must be stored, retrieved, created, and modified while maintaining a consistent data structure. The project therefore provided an appropriate foundation for demonstrating database design, validation, CRUD operations, and application-to-database communication.

Enhancement

The database enhancement focused on improving the reliability and organization of the application's data layer. MongoDB provides the persistent storage for trip information, while Mongoose provides a structured schema that defines the information expected for each trip. This creates a clearer contract between the application and its stored data.

Trip records contain information such as a unique trip code, trip name, length, start date, resort, price per person, image information, and a description. Defining these fields through a Mongoose schema improves consistency and makes it easier to validate information before it is stored in the database.

The enhancement also emphasizes CRUD functionality. The application needs to create new trip records, retrieve existing trips, update trip information, and manage data through its API. Separating these operations into appropriate models, controllers, and routes makes the application easier to maintain and provides a clear path between an HTTP request and the corresponding database operation.

Data Validation and Integrity

Validation is important because an application should not assume that all incoming data is complete or correct. Applying validation at the data-model and application levels helps prevent incomplete or malformed records from being stored. It also provides more predictable behavior when the front end communicates with the API.

The use of a unique trip code provides a reliable method of identifying individual records. API operations can use this identifier to retrieve or update a particular trip without relying on information that may not be unique. This approach improves both data integrity and application reliability.

Error Handling

Another important part of the enhancement is handling situations where database operations do not produce the expected result. A requested trip may not exist, required information may be missing, or a database operation may fail. Appropriate error handling allows the API to return meaningful responses instead of failing silently or exposing unnecessary implementation details.

Considering these scenarios strengthened the reliability of the data layer and reinforced the importance of designing database interactions around both successful and unsuccessful outcomes.

Technical Skills Demonstrated

This enhancement demonstrates my ability to work with a NoSQL database, design data models using Mongoose, implement CRUD functionality, validate application data, and connect database operations with RESTful API endpoints.

It also demonstrates my understanding of the relationship between the database and other layers of a full-stack application. The database is not an isolated component. Changes to the data model can affect API controllers, services, Angular components, and the overall user experience.

Course Outcomes

The database enhancement supports the CS 499 course outcomes by demonstrating my ability to design and evaluate computing solutions that use appropriate technologies and development practices. It also demonstrates my ability to create solutions that manage information reliably while considering maintainability, validation, security, and the needs of application users.

The enhancement connects database development with software engineering and algorithmic thinking. Effective applications require developers to consider how information is stored, how efficiently it can be retrieved, how it will be processed, and how other components will interact with that information.

Reflection

Working on the database enhancement strengthened my understanding of how important data design is to the overall quality of an application. Earlier in my development experience, it was easy to think of a database primarily as a location for storing records. Through this project and other coursework, I developed a better understanding of how schemas, validation, identifiers, CRUD operations, and error handling influence the reliability of the entire system.

This enhancement also showed me the importance of planning the relationship between an application's data layer and its other components. A well-designed database interface makes future development easier because other parts of the application can depend on predictable data structures and responses. These are skills I will continue to use when developing applications that rely on persistent data.
